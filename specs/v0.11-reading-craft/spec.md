# Spec: v0.11 极致阅读工艺（Reading Craft）

- **关联意图**：[intent.md](./intent.md)
- **状态**：`Approved`（已确认）
- **适用平台**：macOS、Windows、Linux（Tauri 2 桌面端）

---

## 1. 术语与范围约定

- **阅读视图（Reading View）**：当前已打开某篇 Markdown 文件（`filePath` 非空）且正在渲染正文（`.md-reader__markdown-content`）的状态。
- **知识库首页（Workspace Home）**：已打开工作区目录（`folderPath` 非空）且当前未打开具体文件（`filePath` 为空）的状态。
- **快捷键约定**：下文 `Mod` 表示 macOS 上的 `⌘`（`metaKey`），Windows/Linux 上的 `Ctrl`（`ctrlKey`）。

---

## 2. 功能需求（Functional Requirements）

### FR-1：页内查找（In-page Find）

让用户在阅读长文时，可以快速定位、浏览当前文档内的所有匹配项。

#### 交互与行为
1. **唤起与关闭**：
   - 在阅读视图中按下 `Mod+F`，打开页内查找浮条（固定在阅读区右上角、工具栏下方），并自动聚焦输入框；若输入框已有内容则全选文本。
   - 若页面中存在用户已选中的单行短文本（≤ 80 字符且不含换行）且查找浮条未打开，按 `Mod+F` 时自动填入该选中文本。
   - 若当前不在阅读视图（欢迎页或知识库首页），`Mod+F` 不打开页内查找浮条（保持无干扰）。
   - 按 `Esc` 或点击关闭按钮，关闭浮条、清除所有页内查找高亮，并将焦点交回阅读区。
   - 当全局搜索弹窗（`Mod+K`）、新建工作区弹窗、设置抽屉或媒体灯箱打开时，`Esc` 优先关闭最上层模态层，不越级误关底层状态。
2. **匹配与高亮**：
   - 输入关键词后（去首尾空白前保留空格，仅全空白视为无查询），在当前文章正文中执行**大小写不敏感的纯文本子串匹配**（支持中文、英文、正则特殊字符如 `a+b`、`[foo]`、`C++` 等字面量匹配）。
   - 仅匹配可见正文文本，跳过 `script`、`style`、Mermaid SVG 内部隐藏/重复节点、按钮 chrome（如代码块 Copy 按钮）以及 KaTeX 的不可见 MathML 分支，避免出现重复命中或破坏公式/图表 DOM。
   - 所有匹配项使用高亮标记，当前选中项使用更醒目的激活态高亮，并自动平滑滚动（遵守 `prefers-reduced-motion`）到可视区域中央。
   - 浮条展示匹配计数：有匹配时显示 `当前序号 / 总数`（如 `2 / 14`）；有输入但无匹配时显示 `0 / 0`（无匹配样式提示）。
3. **上下导航**：
   - 在查找输入框中按 `Enter` 或点击「下一项」按钮：跳转到下一个匹配项（到末尾自动循环回第 1 项）。
   - 按 `Shift+Enter` 或点击「上一项」按钮：跳转到上一个匹配项（到开头自动循环到最后 1 项）。
   - 输入法合成中（`isComposing === true`）按 `Enter` 不触发跳转。
4. **生命周期联动**：
   - 切换文档、切换标签页或返回知识库首页时，自动清除旧文档高亮；若新切入的仍是阅读视图且浮条保持打开，则自动对新文档重新执行匹配；若切回首页则关闭浮条。
   - 当前文件被外部编辑器/AI 修改并触发热重载（`watch`）时，若查找浮条处于打开状态，重渲染完成后自动重新执行当前查询并尽量保持接近的匹配序号。
   - 执行「复制为富文本」或「导出 PDF / 打印」时，**不得**将页内查找的高亮样式或浮条带入导出/复制结果中。

#### 验收标准（FR-1）
- **AC-1.1**：Given 处于阅读视图，When 按下 `Mod+F` 并输入 `markdown`，Then 浮条打开、所有正文中的 `markdown`（不区分大小写）被高亮、第 1 项为激活态并滚动入视口、计数显示 `1 / N`。
- **AC-1.2**：Given 查找词包含正则特殊字符（如 `v0.11` 或 `a+b`），When 执行查找，Then 按字面量精确匹配且不抛异常。
- **AC-1.3**：Given 当前处于第 `N` 项（最后一项），When 按 `Enter`，Then 循环回到第 `1` 项；When 在第 `1` 项按 `Shift+Enter`，Then 循环到第 `N` 项。
- **AC-1.4**：Given 查找浮条已打开并高亮了匹配项，When 按 `Esc` 或点击关闭按钮，Then 所有高亮标记被彻底还原为普通文本节点，DOM 结构干净且浮条隐藏。
- **AC-1.5**：Given 查找浮条已打开且有高亮，When 点击「复制为富文本」或打印，Then 输出结果中不包含查找高亮标记和查找浮条。

### FR-2：阅读排版精调（Typography Controls）

让用户根据屏幕尺寸、视力习惯和文档类型，独立微调正文阅读舒适度。

#### 交互与行为
1. **设置入口**：位于现有设置抽屉的「阅读（Reading）」分区内，紧接在字体选择下方。
2. **三项参数与取值**：
   - **字号（Font Size）**：范围 `14px` – `32px`，步长 `1px`，默认 `16px`（与 `v0.10.0` 默认一致）；正文段落、标题（H1–H6）、列表、引用、表格与代码块均按比例协调缩放。
   - **正文宽度（Reading Width）**：基于**当前阅读区窗口宽度（`cqi` 容器宽度比例）**的 3 档响应式预设，大屏可真正铺开、小屏自动保底不挤压，默认 `comfortable`：
     - 紧凑（`narrow`）：`clamp(520px, 56cqi, 100cqi)`（带右侧知识回响栏时为 `clamp(840px, 68cqi, calc(100cqi - 48px))`）
     - 适中（`comfortable`）：`clamp(680px, 74cqi, 100cqi)`（带右侧知识回响栏时为 `clamp(960px, 82cqi, calc(100cqi - 48px))`）
     - 宽屏（`wide`）：`clamp(880px, 94cqi, 100cqi)`（带右侧知识回响栏时为 `calc(100cqi - 48px)`）
   - **行距（Line Height）**：3 档预设，默认 `standard`：
     - 紧凑（`compact`）：`1.5`
     - 标准（`standard`）：`1.65`
     - 宽松（`relaxed`）：`1.85`
   - 提供一个轻量的「恢复默认（Reset）」操作（当任一项偏离默认值时可见/可点），一键恢复三项默认值。
3. **作用范围与隔离**：
   - 仅作用于阅读区正文（`.md-reader__markdown-content` 及其内部排版元素，并同步对齐阅读上下文栏与带知识回响时的阅读宽度），**不得**破坏侧边栏、工具栏、标签栏、弹窗、首页卡片的布局尺寸。
   - **打印 / 导出 PDF 隔离**：`@media print` 仍使用打印专用排版规则，不受宽屏宽度覆盖或过大字号影响导致溢出。
4. **持久化与容错**：
   - 实时预览，修改后持久化保存到 `.settings.dat`。
   - 读取持久化值时做边界校验（非法值、旧版本缺失字段均安全回退到默认值）。

#### 验收标准（FR-2）
- **AC-2.1**：Given 首次升级的用户（无历史排版配置），When 打开任意 Markdown 文档，Then 字号为 `16px`、宽度为 `comfortable`（占阅读区约 76%）、行距为标准档（`1.65`）。
- **AC-2.2**：Given 用户调整字号（范围 `14px–32px`，如 `28px`）、切换宽度档位（含大屏窗口与展开知识回响侧栏场景）、切换行距档位，When 立即观察页面，Then 阅读正文（段落、标题、列表、代码、表格）和宽度实时明显变化且侧边栏/工具栏不变形；When 重启应用，Then 三项配置完整恢复。
- **AC-2.3**：Given 用户配置了非默认值，When 点击「恢复默认」，Then 三项全部恢复默认值并持久化。
- **AC-2.4**：Given 存储中存在非法值（如字号 `999` 或未知宽度枚举），When 应用启动加载，Then 自动修正/回退至合法范围（`14–32`）或默认值，不报错。

### FR-3：图片与 Mermaid 图表灯箱查看（Media & Diagram Lightbox）

让正文中的宽图、截图与复杂 Mermaid 图表可随时放大细看。

#### 交互与行为
1. **触发条件**：
   - 在阅读正文中点击任意普通 `<img>`（**排除**被 `<a>` 超链接包裹的图片，以免劫持图片链接跳转），打开灯箱。
   - 点击任意**已成功渲染**的 Mermaid 图表（`.mermaid-diagram:not(.mermaid-diagram--failed):not(.mermaid-diagram--pending)` 内的可见 SVG），打开灯箱（失败态源码块不触发灯箱）。
   - 鼠标悬浮在可放大图片或 Mermaid 图表上时，光标提示 `zoom-in`。
2. **灯箱交互**：
   - 以原生 `<dialog>` 模态顶层渲染（支持键盘焦点管理与 `::backdrop` 遮罩，适配全部 5 套明暗主题）。
   - 支持 **缩放控制**：
     - 按钮：`−`（缩小）、`100%` / 当前百分比（点击复位 `1:1` 适应视口）、`+`（放大）；
     - 键盘：`+` / `=` 放大、`-` 缩小、`0` 复位；
     - 滚轮（可选 `Mod + 滚轮` 或灯箱内直接滚轮缩放），缩放范围 `50%` – `400%`。
   - 当放大倍数 > 100% 时，支持鼠标按住拖拽平移查看细节。
   - **关闭方式**：点击关闭按钮、按 `Esc`、或点击内容外的暗色遮罩区域。关闭后将焦点交回之前触发元素（若仍在 DOM 中）。
   - 若为图片且存在 `alt` 或 `title`，在灯箱底部轻量展示说明文字；若为 Mermaid 图表，保持高清矢量缩放不模糊，且使用与当前阅读主题一致的清晰背景衬底（确保深色/浅色文字清晰可读）。
3. **切换/导出安全**：
   - 灯箱组件不嵌入在 `.md-reader__markdown-content` 内，不会污染富文本复制、Markdown 原文复制与打印。

#### 验收标准（FR-3）
- **AC-3.1**：Given 文章包含普通本地相对路径图片或网络图片，When 点击该图片，Then 灯箱打开并展示完整图片，按 `Esc` 或点击遮罩关闭。
- **AC-3.2**：Given 文章包含被 `<a>` 包裹的图片徽章（如 README shields.io 图标），When 点击该图片，Then 按既有链接逻辑打开外部 URL，不弹出灯箱。
- **AC-3.3**：Given 文章包含已成功渲染的 Mermaid 流程图，When 点击图表，Then 灯箱以矢量 SVG 形式打开该图表，缩放至 `200%` 依然清晰，并可拖拽平移与点击复位。
- **AC-3.4**：Given 文章包含语法错误的 Mermaid 块，When 点击错误提示/源码块，Then 不触发灯箱（用户可正常选中复制报错源码）。

### FR-4：外部工作流快捷动作（External Handoff）

打通“在 Pyrus 中专注阅读 → 发现需修改时一键去外部工具编辑 → 保存后 Pyrus 自动刷新”的无缝闭环。

#### 交互与行为
1. **动作入口**：
   - 在阅读视图顶部工具栏（或阅读上下文栏，靠近「导出」入口的轻量菜单/按钮组）中，当 `filePath` 有效时提供两项快捷动作：
     1. **用外部应用打开（Open Externally）**：调用操作系统默认关联应用打开当前 `.md` 文件（若系统默认关联为 Pyrus 自身导致自打开，需在文案或行为上说明，并同时提供「在访达/资源管理器中显示」作为可靠备选）。
     2. **在访达 / 资源管理器中显示（Reveal in Finder / Explorer / File Manager）**：打开系统文件管理器并高亮选中当前文件（macOS 显示“在访达中显示 / Reveal in Finder”，Windows 显示“在资源管理器中显示 / Reveal in Explorer”，Linux 显示“在文件管理器中显示 / Show in File Manager”）。
   - 若用户同时设置了「自定义外部编辑器」（可选设置项，留白则用系统默认打开；支持在设置里填写如 `code` / `cursor` / 应用名或留空），则「在外部编辑器中打开」优先用该编辑器打开当前文件；若打开失败则给出明确 Toast 提示而非静默无反应。
2. **错误与边界处理**：
   - 如果文件已被外部移动或删除，点击后展示明确的失败 Toast（不崩溃）。
   - 仅当存在当前 `filePath` 时可见；独立单文件阅读模式与知识库模式均可用。
   - 当用户在外部编辑器修改并保存该文件后，依赖现有 `watch` 机制自动热重载内容（无需额外手动刷新）。

#### 验收标准（FR-4）
- **AC-4.1**：Given 正在阅读本地文件 `/path/to/note.md`，When 点击「在访达 / 资源管理器中显示」，Then 系统文件管理器打开并定位到 `note.md`。
- **AC-4.2**：Given 正在阅读本地文件，When 点击「在外部编辑器打开」，Then 若配置了自定义编辑器则用该编辑器打开文件，否则交由系统默认应用打开；打开失败时显示友好 Toast 提示。
- **AC-4.3**：Given 文件已被删除，When 点击上述任一动作，Then 提示文件无法打开/不存在的 Toast，不抛出未捕获异常。

### FR-5：最近工作区快速切换（Recent Workspaces Switcher）

让拥有多个本地目录（如个人笔记、工作项目、AI 产出目录）的用户一键切换，不用每次走系统目录弹窗。

#### 交互与行为
1. **记录规则**：
   - 每当用户通过「打开知识库」「新建知识库」或拖入目录激活一个工作区时，将该 `folderPath` 记入最近工作区列表首位（去重，跨平台路径规范化比对，最多保留 `8` 个）。
   - 持久化保存在 `.settings.dat` 的 `recentWorkspaces` 中。
   - 当前正在使用的工作区若存在，首次升级迁移时自动成为列表第 1 项。
2. **切换器 UI**：
   - 在侧边栏顶部现有的工作区标题区旁边，提供一个轻量的下拉切换触发按钮（点击原工作区名称仍保持回到「知识库首页」的既有习惯，不破坏肌肉记忆；点击右侧切换箭头/切换器展开工作区菜单）。
   - 下拉菜单内容：
     - 「最近知识库」列表：展示文件夹名 + 省略后的路径提示，标记当前激活的工作区；支持移除某条记录（仅从列表移除，绝不删除磁盘文件）。
     - 分隔线 + 快捷操作：「打开其他文件夹…」「新建知识库…」。
   - 点击列表中任意非当前工作区，直接调用既有工作区激活流程：保存当前工作区的阅读进度与标签页 → 切换到目标工作区 → 自动恢复目标工作区之前保存的标签页、外部源和今日回响。
3. **失效目录容错**：
   - 若点击的最近工作区目录已在磁盘上被删除或不可访问，给出明确 Toast 提示（如「该文件夹已不存在」），保持当前工作区不被破坏，并允许用户将其从列表中移除（或自动提示/提供移除入口）。

#### 验收标准（FR-5）
- **AC-5.1**：Given 用户先后打开了工作区 A 和工作区 B，When 打开侧边栏工作区切换菜单，Then 列表按最近使用顺序展示 B（当前）和 A。
- **AC-5.2**：Given 当前在工作区 B，When 在菜单中点击工作区 A，Then 工作区 B 的标签页被保存，应用切换到工作区 A，并恢复工作区 A 上次打开的标签页与外部源。
- **AC-5.3**：Given 最近工作区列表已有 8 条记录，When 打开第 9 个新目录，Then 新目录排在第 1 位，最旧的一条被淘汰，列表总数保持 8 条；重复打开已有目录仅将其移至首位不产生重复项。
- **AC-5.4**：Given 列表中某目录已在磁盘上被删除，When 点击该目录，Then 显示友好提示 Toast、当前工作区状态不受损。
- **AC-5.5**：Given 用户点击某条非当前记录旁的移除按钮，Then 该记录从列表移除并持久化，磁盘上的原目录不受任何影响。

## 3. 非功能需求（Non-Functional Requirements）

- **NFR-1（双语一致）**：所有新增 UI 文案、按钮 `aria-label`、Tooltip、Toast 均须同时提供高质量的**简体中文**和**英文**词条（[src/lib/i18n.svelte.ts](file:///Users/gtechoogle/Github/markdown_reader/src/lib/i18n.svelte.ts)），并跟随现有 `locale` 切换即时更新。
- **NFR-2（无障碍与键盘友好）**：
  - 页内查找浮条、媒体灯箱、工作区下拉菜单均支持键盘操作与 `Esc` 关闭，遵守 `prefers-reduced-motion`（关闭平滑滚动/过渡动画）。
  - 全部新增视觉样式使用既有 CSS 变量（`--color-bg`、`--color-primary`、`--color-border`、`--color-side-bg`、`--color-mark` 等），在 5 套主题（Light / Dark / Newsprint / Terminal / Glass）下均保持足够对比度。
- **NFR-3（隐私与本地优先）**：所有新增功能 100% 本地运行，不引入任何网络请求、外部依赖下载或遥测。
- **NFR-4（性能与零回归）**：
  - 页内查找在 20,000 字长文档中响应流畅（无明显输入卡顿）；
  - 既有导出（PDF / 富文本 / Markdown）、多标签、知识回响、全局搜索、`node:test` 与 `cargo test` 零回归。
