# Intent: v0.11 极致阅读工艺（Reading Craft）

- **版本 / 周期**：`v0.11`（路线三：跨平台极致 Markdown 阅读器第一期）
- **状态**：`Approved`（已确认）
- **前置基线**：`v0.10.0`（已具备多标签、最近变化、PDF/富文本导出、知识回响、文件监听热重载）

---

## 1. 背景与要解决的问题

Pyrus / 知返的长期演进路线已明确为：**先打牢「跨平台极致 Markdown 阅读器」（路线三），再自然生长出「AI 时代 Markdown 审阅台」（路线二）**。

在 `v0.10.0` 上，Pyrus 已经具备不错的外观、多标签、全局搜索和导出基础，但当用户真的把它设为 **Windows / macOS 默认 `.md` 阅读器**、每天用来读长文档和技术/AI 报告时，仍存在 5 个高频“卡手”的断点：

1. **长文里找不到词**：有全局搜（`⌘K`），但缺当前文章内的页内查找（`⌘F` / `Ctrl+F`）。
2. **阅读版式不可微调**：能换主题和字体，却不能调**字号、正文宽度和行距**，不同屏幕尺寸（笔记本 vs 4K 宽屏）下阅读舒适度受限。
3. **宽图与复杂 Mermaid 看不清**：技术文档和 AI 产出大量包含架构图、流程图、宽截图，当前只能挤在正文栏里，无法点击放大细看。
4. **“只读”与“顺手改两字”之间断档**：发现文档错别字或需要编辑时，虽然 Pyrus 已有文件热重载，却无法一键跳到外部默认编辑器或在访达/资源管理器中定位文件。
5. **切换不同目录成本高**：底层已按工作区隔离保存标签页与外部源，但用户同时看“个人笔记”和“工作/AI 产出目录”时，每次都要重新打开系统文件选择器。

---

## 2. 目标用户与核心价值

- **目标用户**：
  - 在 Windows / macOS / Linux 上寻找比记事本、VS Code、浏览器插件更舒服的本地 `.md` 默认阅读器的用户；
  - 每天在多个本地目录间切换、高频阅读技术文档与 AI 生成 Markdown 的开发者/知识工作者。
- **核心价值**：
  - 让 Pyrus 成为一个**无明显短板的日常默认 Markdown 阅读器**，先把装机留存和口碑立稳；
  - 为下一阶段（路线二：分屏对照、阅读态 Diff、划词批注给 AI）打好阅读区交互与多工作区底座。

---

## 3. 本期目标范围（In Scope）

保持本期轻量、高投入产出比，聚焦以下 5 项核心能力：

1. **页内查找（In-page Find）**：`⌘F` / `Ctrl+F` 呼出轻量浮条，支持当前文档高亮匹配、计数、`Enter` / `Shift+Enter` 上下跳转与 `Esc` 退出。
2. **阅读排版精调（Typography Controls）**：在设置抽屉增加**字号、正文宽度、行距**调节，实时生效并持久化（且不影响打印/PDF 既有排版规则）。
3. **图片与 Mermaid 图表灯箱查看（Media Lightbox）**：点击正文图片或已渲染的 Mermaid 图表，可弹出灯箱放大/缩放/复位查看，`Esc` 或点击遮罩关闭。
4. **外部工作流快捷动作（External Handoff）**：阅读工具栏/上下文中提供「在系统默认应用/外部编辑器打开」和「在访达/资源管理器中显示」，改完保存由现有 `watch` 自动刷新。
5. **最近工作区快速切换（Recent Workspaces）**：自动记录最近打开过的知识库目录，在侧边栏顶部工作区入口即可一键切换，切换时无缝恢复对应工作区的标签页与外部源。

---

## 4. 明确不做什么（Non-goals）

为了防止范围膨胀，以下内容**明确不在 `v0.11` 实现**，留待后续迭代：

- ❌ **不做内置 Markdown 编辑器**：坚持 Read-first，编辑通过外部编辑器衔接解决。
- ❌ **不做路线二审阅功能**：左右分屏、阅读态 Diff、划词批注、MCP 联动留到 `v0.12`。
- ❌ **不做全局搜索语法重写 / 语义检索**：多词 AND 检索、本地 Embedding 回响升级另立独立 Spec。
- ❌ **不做自定义 CSS 文件注入 / Frontmatter 元信息卡片 / 双链图谱**：先守住最高频的通用阅读体验。
- ❌ **不做侧边栏扫描深度重构（Rust 目录树懒加载）**：单列技术优化项，避免与本次 UI 功能耦合过大。
- ❌ **不做商业化付费墙 / License 激活**：先做实阅读器体验与留存，待路线二成型后再切入收费。

---

## 5. 成功标准（Success Criteria）

- **体验完整度**：在 macOS 和 Windows 上，阅读一篇带长文本、代码、图片和 Mermaid 图的 `.md` 文档时，找词、调版式、放大看图、跳外部编辑器修改并自动刷新、切换另一个本地目录，全链路顺滑无报错。
- **向后兼容**：升级后原有 `.settings.dat` 配置（主题、字体、标签页、阅读进度、回响偏好）零丢失；原有 PDF 导出与富文本复制不受排版设置和灯箱 DOM 污染。
- **工程与验证标准**：
  - 新增纯逻辑（页内查找匹配/排序、排版参数校验、最近工作区列表管理等）全部具备 `node --test` 单元测试；
  - 新增/修改的 Rust 命令具备单元测试或 `cargo test` 通过；
  - `npm run check`、`npm run build`、`cargo check` 全绿，无回归。
  - 在实现过程中顺手将新增的独立 UI/逻辑模块拆出到 `src/lib/` 与独立 Svelte 组件，不再继续无节制堆大 `src/routes/+page.svelte`。
