# Pyrus 核心阅读流程审查

审查范围：已安装 Pyrus 0.8.3，macOS 中文界面，1000×700 现有窗口；知识库首页、继续阅读、文章、⌘K 搜索、知识回响与返回。结合当前源码。建议性审查，不实施代码修改。

## 设计判断

Pyrus 有自己的气质：暖白纸感、克制绿色、本地知识关联，适合安静阅读。下一轮应提升阅读连续性，而非换视觉风格。正文层次、准确恢复阅读位置、⌘K 与“返回刚才的阅读”应保留。

## 优先问题

### [P1] 键盘操作没有形成闭环

src/routes/+page.svelte:1597、1615、1623 的结果、文件和文件夹为 click-only li。原生可访问性树验证文件不是可激活控件，但旁边固定按钮可聚焦。1917 的 dialog open 未形成真正模态焦点约束；1123–1129 已有初始聚焦与返回焦点，应该保留。

影响：不使用鼠标时无法浏览文件树，搜索时可能进入遮盖下的背景控件。

建议：文件激活与固定拆为相邻独立控件；文件夹使用语义按钮并暴露展开状态；完整方向键、Enter、Escape、Tab 与可见焦点。命令：$impeccable harden。

### [P1] 跳转失败缺少恢复出口

src/routes/+page.svelte:1506–1513 未先分类链接协议，未拆分 Markdown 文件路径和 #锚点；571 的读取失败展示原始异常、缺少重试，并可能保留上一篇目录。233–235 将侧栏搜索错误降为无结果。此项来自代码路径，未故意触发运行错误。

影响：读者无法区分内容不存在、搜索失败还是链接处理失败，阅读上下文易断裂。

建议：正确处理协议和文件锚点；保留最后成功文章状态，提供本地化重试、定位文件和返回入口。命令：$impeccable harden。

### [P2] 继续阅读没有进入首页首屏

实测 1000×700 首屏被知识库标题、完整路径、来源和今日回响占据。1757 才出现继续阅读；300 的列表只按最近时间排序，包含 0% 和100%。

影响：有明确任务的回访用户需要先滚动，继续与最近阅读语义重复。

建议：标题附近一条紧凑“继续上次阅读：标题 / 进度”；保留今日回响主卡，续读只收纳未读完的文章。命令：$impeccable layout / $impeccable clarify。

### [P2] 搜索摘要不利于辨认

实测搜索“记忆”出现字面上的 <strong> 标签、同一文章多条相似结果。src/routes/+page.svelte:1931 直接文本输出摘要；src-tauri/src/lib.rs:440 从原始命中行截取开头。

影响：读者需要自行剥离标记、比较重复标题，削弱找回旧知识的效率。

建议：安全纯文本摘要、围绕命中词截取、关键词高亮、同名文件显示简短父路径；不直接执行任意 HTML。命令：$impeccable clarify / $impeccable harden。

### [P2] 知识回响遮住了它本应辅助的正文

实测展开卡覆盖段落与标题；某条推荐是同篇中英文版本，摘录是代码目录。src/routes/+page.svelte:2385 普通宽度采用 fixed；2428 足够宽的阅读容器才变为独立栏。

影响：用户停止阅读去处理提示，但推荐未必提供新的关系。

建议：收起时保持安静；普通窗口展开为明确、可立即返回的临时查看层，不作为边读边看的遮挡卡；宽窗口独立侧栏。改善正文摘要，降低翻译/近重复的推荐优先级。命令：$impeccable shape / $impeccable distill。

## 用户视角

- 新用户：继续与最近阅读不易区分；侧栏“搜索文件”其实搜索全文。单篇模式下可见知识库但全局搜索禁用，缺少原因解释。
- 高频读者：首页续读额外滚动；搜索与准确恢复滚动位置值得保留。
- 键盘用户：文件和目录缺少原生活动语义；搜索焦点约束需补。未执行完整 VoiceOver 测试。

认知负担主要集中在正文之外：重叠的续读/最近列表、重复搜索结果，以及展开回响与正文争夺焦点。情绪路径：进入个人空间的安静感 → 找续读的小阻力 → 正文专注 → 搜索标记与回响遮挡的落差 → 明确返回带来的安心。

## 扫描与补充

Impeccable 源码扫描返回 []，0发现、无误报，不代表通过无障碍检查。人工审查补足了键盘、焦点、链接和异常恢复。依据最新 Vercel Web Interface Guidelines，不机械套用网页 URL 状态要求到桌面阅读器。

回响反馈与隐私文案部分仅7–9px，应提高可读性。目录/搜索跳转使用 smooth 时也应尊重减少动效偏好。现有全局焦点样式、减弱动效与标题滚动偏移已存在，不能误报为全部缺失。
